An internal AI assistant for finding product configurations and preparing traceable cost estimates.

THE PROJECT IN 20 SECONDS

Built a conversational catalog assistant that helps users find compatible configurations, manage a draft, and review internal estimated costs. The application was released and tested; post-release model initialization remains an operational limitation.

01 / CASE STUDY

The problem

Product configuration catalogs are difficult to search manually. One selected option may contain multiple components with quantities, units, credits, labor entries, and estimated costs. An approximate text match is not enough when users need the correct configuration for a particular product context.

Goal: let a user search conversationally and prepare an internal estimate without inventing missing data or turning source costs into customer prices.

02 / CASE STUDY

What I designed and built

Retrieval with guardrails

Combined semantic discovery with deterministic lookup for exact option identifiers and context-aware filtering.

Multi-step conversations

Used LangGraph state to support search, selection, add/remove operations, review and recovery after an unsuccessful search.

Reliable calculations

Kept component quantities, signed credits, zero values, unknown costs and source provenance intact; used deterministic arithmetic.

Release engineering

Added regression coverage, a GitHub Actions CI pipeline, security checks, GitFlow PRs and an annotated v1.0.0 release.

Natural-language models help users express intent. Structured retrieval and deterministic application rules determine which catalog records are eligible and how component totals are calculated.

Important design choice: estimated manufacturing costs are never presented as approved selling prices. The MVP does not issue customer quotations or priced CSV exports.

04 / CASE STUDY

What was verified

Testing covered exact-code and vessel-context matching, group addition/removal, cost-preservation edge cases, conversational recovery and blocked customer-facing outputs. The release also included a transitive dependency vulnerability fix.

These results establish engineering acceptance for the evaluated release, not proven business impact or adoption.

05 / CASE STUDY

Current boundaries and next steps

The released MVP is for internal estimation only. The commercial pricing and customer quotation platform is deliberately out of scope.

A later supervised run observed an unexpected large Hugging Face download during search, delaying the first retrieval. The exact model/cache root cause remains unverified. The next operational priority is artifact pinning, cache readiness and clear search-time feedback.

Engineering lesson

A source-code release and passing CI are necessary, but model artifacts, data snapshots and runtime readiness determine whether a user can actually complete the task.

Confidential source code, catalog data and real internal pricing are excluded from this public case study.
